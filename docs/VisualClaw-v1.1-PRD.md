# VisualClaw v1.1 PRD

- **版本**：v1.1
- **日期**：2026-05-08
- **状态**：草案
- **项目名**：VisualClaw
- **目标平台**：Windows / WSL
- **产品形态**：轻量桌面客户端 + 本地 Web UI

## 1. 产品概述

### 1.1 背景
OpenClaw 已具备基础控制台能力，但在层级、导航、文案、日志可读性、任务流表达和对话式交互方面仍有提升空间。V1.1 目标是在复用现有能力基础上，完成体验收敛与聊天能力补齐。

### 1.2 产品目标
- 一眼看懂当前状态
- 快速找到下一步操作
- 降低日志和任务排障成本
- 统一术语为人话
- 增加可聊天、可追问、可辅助执行的入口

### 1.3 产品定位
VisualClaw 是面向 OpenClaw 的可视化操作中心，不是纯展示面板。V1.1 重点解决：
- 看不懂当前状态
- 不知道下一步做什么
- 日志和任务不够可读
- 缺少自然语言交互

## 2. 需求总览

### 2.1 当前问题与解决方案

| 问题 | 解决方案 |
|---|---|
| 层级太散 | 首页改为“总览 + 当前任务 + 风险提示”三段式 |
| 导航重复 | 保留一套主导航，顶部仅保留全局搜索/状态/聊天入口 |
| 术语太技术 | 统一状态词：在线、连接中、只读、失败、暂停 |
| 日志难读 | 分级、折叠、过滤、关键词高亮、错误优先 |
| 任务像清单 | 改为任务流/阶段视图，突出卡点与下一步 |
| 连接管理堆叠 | 采用“当前状态 → 候选目标 → 手动兜底”流程 |
| 视觉权重混乱 | 主操作高亮，危险操作降权并二次确认 |
| 缺少聊天 | 增加全局 Chat 助手，可问可控 |

## 3. UML 用例模型

- **普通用户**：查看状态、管理任务、查看日志、发起聊天

## 4. 详细用例规格

### UC-01 查看控制台总览
| 项目 | 内容 |
|---|---|
| 用例编号 | UC-01 |
| 参与者 | 普通用户 |
| 前置条件 | 用户已进入控制台 |
| 后置条件 | 用户了解当前状态、风险与下一步 |
| 基本事件流 | 1. 用户进入首页<br>2. 系统展示总览卡片、风险提示、当前任务<br>3. 用户点击某卡片进入详情 |
| 备选事件流 | 1a. 数据加载失败：显示空态与重试按钮 |
| 业务规则 | 首页只展示最关键的 3 类信息 |

### UC-02 查看任务流状态
| 项目 | 内容 |
|---|---|
| 参与者 | 普通用户/管理员 |
| 前置条件 | 存在运行中任务 |
| 后置条件 | 用户明确任务阶段、卡点和下一步 |
| 基本事件流 | 1. 用户进入任务页<br>2. 系统按阶段展示任务流<br>3. 用户展开某任务看详情、日志、重试/取消 |
| 备选事件流 | 1a. 无任务：展示“可创建任务”引导 |
| 业务规则 | 卡住/失败任务置顶；支持按状态筛选 |

### UC-03 查看与筛选日志
| 项目 | 内容 |
|---|---|
| 参与者 | 普通用户/管理员 |
| 前置条件 | 存在日志数据 |
| 后置条件 | 用户定位问题原因 |
| 基本事件流 | 1. 用户进入日志页<br>2. 系统按级别分组展示日志<br>3. 用户按关键字/级别/时间过滤<br>4. 用户展开原文 |
| 备选事件流 | 1a. 日志量过大：默认只展示错误与警告 |
| 业务规则 | 错误优先；原始日志与摘要分层展示 |

### UC-04 管理连接与目标
| 项目 | 内容 |
|---|---|
| 参与者 | 管理员 |
| 前置条件 | 用户具有连接管理权限 |
| 后置条件 | 用户完成连接检查或切换目标 |
| 基本事件流 | 1. 用户打开连接面板<br>2. 系统展示当前连接状态、候选目标、手动目标<br>3. 用户选择目标并确认<br>4. 系统执行连接 |
| 备选事件流 | 1a. 自动连接失败：引导手动兜底 |
| 业务规则 | “当前状态”优先于“候选目标”优先于“手动输入” |

### UC-05 发起聊天咨询
| 项目 | 内容 |
|---|---|
| 参与者 | 普通用户 |
| 前置条件 | 聊天功能可用 |
| 后置条件 | 用户获得答案或建议操作 |
| 基本事件流 | 1. 用户打开 Chat<br>2. 输入自然语言问题<br>3. AI 助手结合上下文回答<br>4. 用户继续追问 |
| 备选事件流 | 1a. 信息不足：助手反问关键缺失项 |
| 业务规则 | 默认结合当前页面上下文回答 |

### UC-06 通过聊天执行操作
| 项目 | 内容 |
|---|---|
| 参与者 | 普通用户/AI 助手 |
| 前置条件 | 用户授权执行操作 |
| 后置条件 | 系统完成查询/切换/重试/打开页面等动作 |
| 基本事件流 | 1. 用户在 Chat 中发出操作请求<br>2. 助手解析意图并给出执行预览<br>3. 用户确认<br>4. 系统执行并返回结果 |
| 备选事件流 | 1a. 危险操作：必须二次确认 |
| 业务规则 | 只允许白名单动作；高风险动作需确认 |

### UC-07 查看配置与状态详情
| 项目 | 内容 |
|---|---|
| 参与者 | 管理员 |
| 前置条件 | 用户进入配置/Agent/Skills 页面 |
| 后置条件 | 用户了解当前配置与影响 |
| 基本事件流 | 1. 用户查看配置项<br>2. 系统显示中文说明、当前值、影响范围<br>3. 用户修改并保存 |
| 备选事件流 | 1a. 权限不足：禁止编辑仅可查看 |
| 业务规则 | 配置项需提供“说明 + 风险 + 影响范围” |

## 5. 交互设计

### 5.1 首页结构
- 顶部：全局状态条（在线/连接中/异常）
- 主区：总览卡片（任务数、告警、连接状态）
- 次区：当前进行中的任务流
- 右侧：Chat 助手入口

### 5.2 全局导航
- 左侧主导航保留一次
- 顶部不再重复同类 tab
- 顶部只保留：搜索、通知、Chat、用户菜单

### 5.3 Chat 交互
- 固定入口：右下角悬浮按钮 + 顶部入口
- 支持：
  - 问状态：现在卡在哪？
  - 查信息：最近失败任务有哪些？
  - 要建议：下一步怎么处理？
  - 执行动作：帮我重试这个任务
- 每次操作前给出可确认预览

### 5.4 日志交互
- 默认折叠长日志
- 优先显示：错误、警告、关键动作
- 支持：关键词高亮、复制、定位到关联任务/会话

## 6. UI 设计规范

### 6.1 布局原则
- 一屏只强调一个主目标
- 信息按“概览 → 详情 → 原文”递进
- 主按钮与危险按钮明确区分

### 6.2 文案规范
统一使用人话：
- `connected` → 在线
- `connecting` → 连接中
- `read_only` → 只读
- `busy` → 忙碌中
- `failed` → 失败
- `paused` → 已暂停

### 6.3 颜色建议
- 主色：品牌蓝
- 成功：绿色
- 警告：橙色
- 错误：红色
- 中性：灰色

### 6.4 组件规范
- 总览卡：小而清晰
- 任务卡：显示阶段、负责人、状态、下一步
- 日志卡：摘要 + 可展开原文
- Chat 卡：上下文、建议、确认按钮

## 7. 数据字典

### 7.1 Chat 会话表 `chat_session`
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| session_id | UUID | 是 | 会话 ID |
| user_id | UUID | 是 | 用户 ID |
| context_page | VARCHAR | 否 | 当前页面上下文 |
| created_at | DATETIME | 是 | 创建时间 |
| updated_at | DATETIME | 是 | 更新时间 |
| status | VARCHAR | 是 | active/closed |

### 7.2 Chat 消息表 `chat_message`
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| message_id | UUID | 是 | 消息 ID |
| session_id | UUID | 是 | 所属会话 |
| role | VARCHAR | 是 | user/assistant/system |
| content | TEXT | 是 | 消息内容 |
| action_ref | JSON | 否 | 关联操作/引用 |
| created_at | DATETIME | 是 | 创建时间 |

### 7.3 任务表 `task_flow`
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| task_id | UUID | 是 | 任务 ID |
| title | VARCHAR | 是 | 任务标题 |
| stage | VARCHAR | 是 | 当前阶段 |
| status | VARCHAR | 是 | pending/running/blocked/done/failed |
| priority | INT | 是 | 优先级 |
| blocked_reason | TEXT | 否 | 卡点说明 |

## 8. 非功能需求

### 8.1 性能
- 首页首屏加载 < 2s
- Chat 首次响应 < 3s
- 日志筛选响应 < 1s

### 8.2 可靠性
- Chat 操作失败可回退
- 关键操作可重试
- 日志与任务数据支持降级展示

### 8.3 安全
- 危险操作二次确认
- Chat 仅允许白名单动作
- 权限不足时仅可查看不可执行

### 8.4 兼容性
- 适配桌面优先
- Chat 在窄屏下转为抽屉/底部面板

## 9. 验收标准

1. 用户能在 5 秒内看懂首页重点
2. 用户不需要猜术语就能理解状态
3. 日志页面能快速定位错误
4. 任务页能看出卡点与下一步
5. Chat 可回答问题并发起受控操作
6. 危险操作均有确认流程
