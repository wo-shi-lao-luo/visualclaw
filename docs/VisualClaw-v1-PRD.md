# VisualClaw v1 PRD

- **版本**：v1.0
- **日期**：2026-05-07
- **状态**：草案
- **项目名**：VisualClaw
- **参考仓库**：https://github.com/openclaw/openclaw
- **目标平台**：Windows / WSL
- **产品形态**：轻量桌面客户端 + 本地 Web UI

## 1. 产品概述

### 1.1 背景
OpenClaw 已经提供了基础的 Web UI，但整体仍偏向原生用户和熟练用户。对于新手来说，安装、连接、查看状态、理解任务、管理 Skills 仍然存在门槛。

VisualClaw 的 v1 目标不是重写 OpenClaw，而是**大量复用 OpenClaw 现有 UI 代码与信息架构**，在此基础上增加更适合桌面场景的 Agent、任务流、Skills 管理能力。

### 1.2 产品目标
- 直接复用 OpenClaw 的基础 UI 骨架，快速形成可用产品
- 保留用户熟悉的首页 / 会话 / 任务 / 日志 / 配置 / 连接管理
- 增加 Agent 控制、任务流监控、Skills 管理中心
- 让用户更容易理解 OpenClaw 当前状态、正在执行什么、如何操作
- 优先支持 Windows / WSL 本地使用场景

### 1.3 产品定位
VisualClaw 是一个面向 OpenClaw 的**可视化操作中心**，而不是纯展示面板。它要解决的问题包括：
- 看不懂 OpenClaw 在做什么
- 不知道从哪里开始操作
- 不方便管理 Agent、任务、Skills
- 连接与诊断成本高

### 1.4 v1 原则
1. **先复用，再增强**
2. **先可用，再好看**
3. **保持 OpenClaw 熟悉感**
4. **让 Agent / 任务 / Skills 成为一等公民**
5. **页面要能联动，不是各看各的**

## 2. 系统范围

### 2.1 v1 包含内容
- 复用 OpenClaw 现有 UI 的基础页面结构
- 首页 / 会话 / 任务 / 日志 / 配置 / 连接管理
- Agent 控制台
- 任务流面板
- Skills 管理中心
- 连接发现、手动连接、重连、诊断
- 基础日志检索与页面联动
- 基础配置查看与编辑

### 2.2 v1 不包含内容
- 插件市场
- 多用户协作
- 复杂工作流编排器
- 远程多实例统一编排
- 高级主题系统
- OpenClaw 全量 CLI 的逐项镜像

### 2.3 复用策略
- **大量复用 OpenClaw 前端代码、页面骨架与交互模式**
- **不 fork 后端实现作为产品核心**
- 后端仍以现有 OpenClaw 能力和接口为基础
- 新功能优先做在前端层和交互层

## 3. 核心用户

- **新手用户**：第一次使用 OpenClaw，希望“看得懂、点得动”
- **熟练用户**：希望比 CLI 更快地管理 Agent、任务、Skills
- **维护者**：关注连接状态、日志、错误定位、恢复路径
- **系统环境**：Windows / WSL，负责发现与连接支持

## 5. 详细用例规格说明

### UC-01 自动发现本机 OpenClaw

| 项目 | 内容 |
|---|---|
| **用例编号** | UC-01 |
| **用例名称** | 自动发现本机 OpenClaw |
| **参与者** | 系统环境、维护者 |
| **优先级** | 高 |
| **前置条件** | 客户端启动 |
| **后置条件** | 发现一个或多个可连接实例，或进入手动兜底 |
| **基本事件流** | 1. 客户端自动扫描本机常见端口。<br>2. 判断目标服务是否为 OpenClaw。<br>3. 若发现多个实例，按优先级排序。<br>4. 显示可用实例和推荐项。 |
| **备选事件流** | 1a. 未发现实例：进入手动连接。<br>2a. 发现异常实例：标记为待确认。 |
| **业务规则** | 1. 优先本机回环地址。<br>2. Windows / WSL 使用不同扫描策略。 |

#### 数据说明表

**本地实例发现结果（local_instance_discovery）**

| 字段名 | 字段中文名 | 数据类型 | 取值范围 | 是否必填 | 备注说明 |
|---|---|---|---|---|---|
| instance_id | 实例 ID | STRING | 任意字符串 | 是 | 本地唯一标识 |
| host | 主机地址 | STRING | IP / localhost | 是 | 探测到的地址 |
| port | 端口 | INT | 1-65535 | 是 | 探测端口 |
| status | 状态 | ENUM | FOUND / PENDING / FAILED | 是 | 发现结果 |
| env_type | 环境类型 | ENUM | WINDOWS / WSL / UNKNOWN | 是 | 运行环境 |
| score | 匹配分 | INT | 0-100 | 否 | 推荐排序用 |

## 6. 交互设计

### 6.1 页面流程

```text
启动 → 自动发现 → 连接成功/失败 → 首页总览
   ├── 会话
   ├── 任务流
   ├── 日志
   ├── 配置
   ├── Agent 控制台
   ├── Skills 管理中心
   └── 连接与诊断
```

### 6.2 核心联动
```text
Agent 详情 ──► 关联任务 ──► 关联日志 ──► 回到 Skills / 配置
任务流面板 ──► 当前阶段 ──► 关联日志 ──► 关联 Agent
Skills 管理 ──► 绑定 Agent ──► 查看影响范围
```

### 6.3 状态机（简化）

```text
未连接 → 发现中 → 已连接 → 任务运行中
  │          │          │          │
  └───────失败/重试 ←────┴──────断线/恢复←────┘
```

## 7. UI 设计规范

### 7.1 页面布局

```text
┌───────────────────────────────────────────────────────────┐
│ VisualClaw                                                │
├──────────────┬────────────────────────────────────────────┤
│ 导航栏        │ 总览 / Agent / 任务流 / Skills / 日志...   │
├──────────────┼────────────────────────────────────────────┤
│ 侧边区        │ 主内容区                                  │
│ 连接状态      │ 列表 / 详情 / 图谱 / 面板                 │
│ 快捷操作      │                                            │
└──────────────┴────────────────────────────────────────────┘
```

### 7.2 组件要求
- 列表要支持搜索
- 详情页要支持返回与联动
- 关键状态用明显标签展示
- 危险动作必须二次确认

### 7.3 视觉原则
- 简洁、克制、信息密度适中
- 状态颜色清晰但不过度花哨
- 强调“可用”和“可恢复”

## 8. 非功能需求

### 8.1 性能
- 启动后应快速进入主界面
- 自动发现不得阻塞 UI
- 列表页切换应保持流畅

### 8.2 兼容性
- Windows / WSL 均可使用
- 支持本机回环连接
- 支持后续桌面封装

### 8.3 安全
- 危险操作需确认
- 连接目标与配置项需明显提示风险
- 不默认开放高风险能力

### 8.4 可靠性
- 连接失败后可重试
- 页面在异常状态下仍可浏览
- 断线后应保留上下文

## 9. 验收标准

1. 用户能直接进入熟悉的 OpenClaw 风格首页。
2. 用户能通过 VisualClaw 查看和管理 Agent。
3. 用户能通过任务流面板看清任务阶段。
4. 用户能管理通用 Skills 与 Agent 私有 Skills。
5. 用户能完成 Skills 的增删查改。
6. 用户能通过日志、任务、Agent 互相跳转定位问题。
7. 用户能完成自动发现与手动连接。
8. Windows / WSL 场景下都能正常使用。
9. 用户能明确感知危险操作与失败原因。
